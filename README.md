# 音游开字母

一个简单、轻量的 AstrBot QQ 群音游开字母猜曲插件。

插件内部名：`astrbot_plugin_music_guess`

## 功能

- 每局随机抽取 8 首歌曲
- 隐藏 Unicode 字母（英文字母、中文汉字、日文假名等）和 ASCII 数字 0-9
- 支持开英文字母、数字与中文 / 日文等文字字符
- 支持按编号猜歌
- 猜完全部歌曲后自动结束
- 可主动结束并公布答案
- 每个 QQ 群游戏状态完全独立
- 不调用 LLM
- 不使用数据库
- 曲库支持从 GitHub / Gitee 自动更新（默认自动选择更新源，可关闭；更新失败自动回退本地曲库）
- 无第三方 Python 依赖（曲库更新仅使用 Python 标准库）

## 支持环境

- AstrBot `>=4.27.3,<5`
- QQ 官方机器人（`qq_official`）

当前版本以 AstrBot `v4.27.3` 为主要开发和测试环境。

## 安装

### AstrBot WebUI

将本插件的 ZIP 包上传到 AstrBot WebUI 的插件管理页面安装。

### GitHub 仓库

仓库地址：

`https://github.com/Ice2974/astrbot_plugin_music_guess`

如果从源码手动安装，请确保插件目录最终为：

```text
data/plugins/astrbot_plugin_music_guess/
```

## 使用方法

所有游戏操作都需要先 @机器人。未 @机器人 的普通群消息不会触发本插件，也不会被本插件拦截。

开始：

```text
@机器人 开字母
```

开字符：

```text
@机器人 开 A
@机器人 开 7
@机器人 开 桜
```

@机器人 后英文字母和数字可以省略空格（如 `@机器人 开A`、`@机器人 开7`）；中文 / 日文等文字字符需要保留空格（如 `@机器人 开 桜`），以避免误识别。

猜歌：

```text
@机器人 3 Credits
@机器人 1. Credits
@机器人 曲 3 Credits
```

编号和曲名之间用空格、`.` 或 `、` 分隔都可以。

结束：

```text
@机器人 结束开字母
@机器人 结束游戏
```

AstrBot 自身的 `/` 开头指令始终交给 AstrBot 处理，不受插件影响，例如：

```text
@机器人 /help
@机器人 /plugin
```

`@机器人 /xxx` 不会进入游戏逻辑。

### 默认模式（exclusive_mode=false）

插件只处理 @机器人 且明确属于开字母游戏的消息：`@机器人 开字母` 随时可触发；开字符（如 `@机器人 开 A`）、猜歌（如 `@机器人 3 Credits`）和结束（如 `@机器人 结束游戏`）只在本群有进行中的游戏时处理。

没有进行中的游戏时，上述快捷格式以及其他 @机器人 但无法识别的消息都不会被本插件拦截，会正常交给 AstrBot 的其他插件或 AI 对话处理，适合大多数公开 Bot。

### 独占模式（exclusive_mode=true）

开启后，@机器人 但无法识别为游戏指令的消息会由本插件接管：返回玩法提示，并停止事件传播，不进入 LLM。未 @机器人 的消息本插件完全不处理，`@机器人 /xxx` 等 AstrBot 指令仍会放行。

适合只用于开字母游戏的专用 Bot。默认关闭，可在 AstrBot WebUI 的插件配置中开启。

## 曲名隐藏规则

Unicode 字母和 ASCII 数字 0-9 使用 `•` 隐藏：

```text
Credits
•••••••

World Vanquisher
••••• ••••••••••

千本桜
•••
```

规则：

- 所有 Unicode 字母（英文字母、中文汉字、日文假名等）都参与隐藏，可通过 `@机器人 开 桜` 等方式开启
- 英文字母大小写视为同一字符
- ASCII 数字 0-9 默认隐藏，也可通过 `@机器人 开 7` 等方式开启；非 ASCII 数字（如全角 `９`）不隐藏，直接显示
- 空格直接显示
- 标点和符号直接显示
- 已猜中的歌曲显示完整原标题

## 答案匹配规则

- Unicode NFKC 规范化
- 英文字母忽略大小写
- 忽略首尾空白
- 连续空白折叠为一个空格
- 弯引号（’ ‘ “ ”）与直引号视为相同，兼容手机输入法自动转换
- 其余标点必须正确
- 当前不支持别名
- 当前不支持模糊匹配

## 曲库

`songs.txt`：

- UTF-8 编码
- 一行一首歌曲
- 空行自动忽略
- 完全相同的重复行自动去重
- 至少需要 8 首有效歌曲

修改 `songs.txt` 后重载插件即可重新读取。

当前仓库自带的曲库是离线 fallback 曲库，用于远程曲库无法下载、本地缓存不可用等情况下保证插件仍可正常游戏。正式多音游曲库的数据来源和许可信息见 [`SOURCES.md`](SOURCES.md)。

### 曲库自动更新

插件在加载（含重载）时会按 `songs_update_source` 配置检查远程曲库更新：

- 更新源为 GitHub 主仓库与 Gitee 镜像（GitHub → Gitee 单向同步），远程文件同样是 `manifest.json` + `songs.txt`
- `manifest.json` 只包含 `version`、`song_count`、`sha256` 三个自动更新元数据字段；`songs.txt` 仍是一行一首的纯文本，不引入结构化歌曲数据
- 下载内容必须通过 SHA-256、UTF-8 解码、去重数量等完整校验后才会生效
- 远端版本不高于本地时不下载：首次安装时自带曲库与远端同版本，因此不会重复下载、也不会生成缓存
- 整个更新流程受约 20 秒总预算约束（manifest 探测窗口约 6 秒、单次下载约 12 秒），超时自动放弃；任何网络、镜像或校验失败都会回退本地已有曲库，不影响游戏

有效曲库的加载顺序：

```text
远程最新曲库（校验通过后写入缓存）
    ↓
持久化缓存曲库与插件自带曲库按 manifest 版本择高（并列取缓存）
    ↓
插件自带 songs.txt 兜底
```

缓存位于 AstrBot 插件数据目录：

```text
data/plugin_data/astrbot_plugin_music_guess/
├── manifest.json          # 唯一提交点
└── songs-<sha256>.txt     # 内容寻址的歌曲数据
```

缓存采用内容寻址存储：先完整写入新的 `songs-<sha256>.txt`，最后原子替换 `manifest.json` 作为唯一提交点。因此歌曲写入失败、manifest 替换失败、甚至更新中途被超时截断，都不会破坏已有的有效缓存；残留的孤儿文件会在下次更新成功后清理。两个文件的替换各自只保证单文件原子，不构成跨文件事务——这正是加载时对 manifest 与歌曲文件做整组校验（SHA-256、编码、数量）的原因，任何错位都会被整组作废并回退自带曲库。

缓存目录与插件安装目录分离，插件更新或重装不会清除已下载的曲库缓存。

## 游戏状态

游戏状态只保存在 AstrBot 进程内存中：

```text
group_id -> GameState
```

因此：

- 不同 QQ 群互不影响
- AstrBot 重启、插件重载或插件停用后，正在进行的游戏会丢失

这是当前版本的有意设计，不需要数据库。

## 配置

插件目前有两个配置项，可在 AstrBot WebUI 的插件配置页面修改：

- `exclusive_mode`（独占模式，默认 `false`）：开启后，@机器人 但无法识别的消息会返回玩法提示并停止事件传播，不再进入 LLM 或其他插件；未 @机器人 的消息本插件完全不处理。适合仅用于开字母游戏的专用 Bot。普通公开 Bot 推荐保持默认关闭。

- `songs_update_source`（曲库更新源，默认 `auto`）：插件加载时按所选源检查并更新曲库。选项：

  - `自动选择更新源`（auto，默认）：并发探测 GitHub 与 Gitee 的 `manifest.json`，优先版本较新的源；版本相同且内容一致时优先 Gitee，内容不一致时以 GitHub 主上游为准；首选源下载或校验失败时会尝试另一个已探测成功的源
  - `从 GitHub 更新`（github）：只使用 GitHub，失败不切换 Gitee
  - `从 Gitee 更新`（gitee）：只使用 Gitee，失败不切换 GitHub
  - `不更新`（disabled）：完全禁用自动更新，加载时不发起任何曲库相关网络请求

  任何更新失败都会回退本地已有曲库。修改配置后需重载插件生效。
